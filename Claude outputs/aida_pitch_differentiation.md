# AIDA（DIGIT）差別化ピッチ資料 — 文言・対比案

## 1. コアメッセージ（一言で言うなら）

> 「チャットからタスクを拾う」のはどのツールもできる。
> AIDAが違うのは、**拾った後に人の状況（負荷・有給・心情）まで読んで計画を組み直す**こと。

チャット取り込み・AI整理・起票は「入口」であって「本体」ではない、という位置づけに変える。

---

## 2. 対比表（スライド1枚用）

| | 既存の汎用ツール（Notion AI, 汎用Slack Bot等） | AIDA |
|---|---|---|
| チャットからタスク化 | ○ できる | ○ できる（入口にすぎない） |
| 期限延長・フォロー要請の検知 | × 本人が言わないと気づけない | ○ 「このタスクに関する意見」欄からAIが意図を読み取り、責任者に自動で提案 |
| 延長判断の材料 | × 人力で他タスク・休暇を確認 | ○ プロジェクト締切・本人の他の未完了タスク・**有給休暇予定日**をAIが突き合わせ、現実的な代替日まで提案 |
| 断り方 | × 「延長不可」で終わりがち | ○ 「希望日は難しいが、この日までなら」と必ず代替案を出す設計 |
| スケジュール調整の視点 | タスク量だけ | タスク量 ＋ 本人の心情（フォロー要請・SOS）＋ 有給予定 |

## 3. 具体的な機能名・訴求フレーズ案

- 「心情配慮スケジューリング」「SOSを拾うAI」「有給を守るタスク管理」など、既存機能に名前をつけて一つの塊として見せる。
- 実際の画面用語との対応：
  - タスク詳細の「このタスクに関する意見」欄 → ここに書かれた愚痴・SOS・期限延長希望をAIが検知（`extracted_intent`）
  - プロジェクト詳細の「期限延長リクエスト」パネル → AIが希望日の妥当性を、他タスクの混み具合・有給予定日まで見た上で判断し、責任者に代替日を提案
  - AIおすすめ計画ページ → 締切・優先度だけでなく、上記の意図抽出結果を着手日提案の理由に反映

## 4. Q&A想定（審査員の疑問への回答）

**Q. 結局これはNotion AIやZapierでも作れるのでは？**
A. 「メッセージ→タスク化」だけならできます。AIDAの本体は、その先で「担当者の他の予定・有給・心情的なサインまで踏まえて、責任者の代わりに調整案を出す」部分です。単なる自動化ではなく、人間のマネージャーがやっていた「気配り」の代替を狙っています。

**Q. AIの判断は信用できるのか？**
A. すべてのAI提案は「承認待ち」ステータスで止まり、人間（プロジェクト責任者・本人）が確認・承認するまで確定しません。期限延長も「AIのおすすめ」を人が最終判断する設計です。

**Q. 取り込んだメッセージのセキュリティは？**
A. OAuthトークンはAES-256-GCMで暗号化して保存。取り込んだメッセージ本文はタスク化の判定にのみ使用し、恒久保存はしていません（必要であれば実装側で保存ポリシーを明記）。
