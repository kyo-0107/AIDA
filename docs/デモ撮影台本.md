# デモ撮影台本（撮影日: 2026-09-11 金）

Slack / Teams / Gmail / Outlook の4ツールから計11件のタスクを自動起票させ、AIおすすめ計画とSOS検知まで見せるための台本。
文面はコピペしてそのまま送れる形にしてある。日付を変える場合は「2. タスク一覧」の締切だけ直せばよい。

---

## 1. 撮影前チェックリスト

### プロジェクト設定
- [ ] プロジェクトを作成（例: `HACKATHON 2026 / AIDA開発`）
- [ ] **プロジェクト全体の締切を `2026-09-16` に設定** ← SOS検知デモで「提出期限を超える」判断をさせるために必須
- [ ] メンバーを登録（片山・田中・渡邊・ラファエル）。撮影で操作するアカウントがプロジェクト**オーナー**であること
- [ ] SlackチャンネルIDをプロジェクトに設定（`projects.slack_channel`）。未設定だと📝を押しても「チャンネルに紐づくプロジェクトが見つかりません」と返る

### 連携設定
- [ ] `/profile` の「連携アカウント」で Teams / Outlook / Gmail を接続
- [ ] プロジェクト詳細画面で、Teamsの監視チャンネル・Outlookの監視フォルダ・Gmailの送信者フィルタを有効化
- [ ] Bot を起動（`cd digit-app && python3 -m bot.app`）
- [ ] Web を起動（`cd web && npm run dev` → http://localhost:3001）

### ハマりどころ（ここで失敗しやすい）
- **Teams / Outlook は Bot 起動前の既存メッセージを遡らない。** 初回ポーリングは `last_synced_at` を記録するだけなので、**Bot を起動してから送信**すること。検知は最大2分後。2通まとめて送れば1回のポーリングで両方取り込まれる
- **Gmail は未読メールだけが対象**（`is:unread`）。送ったメールを開いて既読にしないこと。かつ自動ポーリングが無いので手動で叩く（2通あっても1回でまとめて取り込まれる）:
  ```bash
  curl -X POST http://localhost:3001/api/poll-gmail -H "Authorization: Bearer <POLL_SECRETの値>"
  ```
- **Slackは📝（`:memo:`）リアクション**で起票。他の絵文字では動かない
- **「かかる時間」「担当」「依頼元（取引先）」は本文から自動抽出されない。** AIおすすめ計画・AI優先度判断の材料にするには、仕込みの段階でタスク編集画面から下の表の「時間」「担当」「取引先」を手で入れておく
  - 「依頼元」欄がそのまま「取引先」の入力欄（自由記述）。`priority.ts` は「依頼元が重要な取引先・クライアントからの依頼と読み取れる場合は優先度を上げる」判断をするので、入れておくとAI優先度判断のデモに説得力が出る
- 4ツールすべて `承認待ち` で登録される。承認デモ用に**最低1件は承認せずに残しておく**

## 4. SOS検知・期限延長デモの手順

差別化の一番の見せ場。**前提条件を満たしていないとAIの提案ボタンがエラーになる**ので順番どおりに。

### 事前準備
1. `/profile` →「有給休暇」で **付与日数を 10 日** に設定
2. 同じ画面で **休み予定日を `2026-09-17` と `2026-09-18` に登録**（未来日のみ有効）
3. タスク #2「Supabase RLSポリシーの確認」の**担当者が、上の有給を登録したアカウント**になっていることを確認
4. プロジェクトの締切が `2026-09-16` になっていることを確認

### 撮影の流れ
1. 担当者アカウントでタスク #2 を開き、「このタスクに関する意見」に次を入力して保存

```
Supabase の RLS のところで詰まっていて、正直このままだと9/15には間に合わないです。
9/18(金) まで伸ばしてもらえないでしょうか。
認証まわりは一人だと判断に自信がないので、できれば誰かに一緒に見てもらいたいです。
```

2. 保存するとAIが意図を抽出し、タスク詳細に「**AIが読み取った意図: フォロー要請・期限延長希望**」と「希望期限: 2026-09-18」が表示される
3. **プロジェクトオーナーのアカウント**でプロジェクト詳細画面を開くと「期限延長リクエスト」パネルにこのタスクが出ている
4. 「**✨ AIに延長可否を提案してもらう**」を押す → AIが次を突き合わせて判断する
   - 本人の希望日 9/18
   - プロジェクト締切 9/16 → **希望日が締切を超えている**
   - 本人の有給予定 9/17・9/18 → **希望日が休み予定と重なっている**
   - 担当者の他の未完了タスク（#1・#7・#9 が片山に寄っているので「過密」の材料になる）
5. 「希望日どおりは難しいが、この日までなら」という**代替日つきの提案**が返る。ここが「既存ツールとの違い」スライドの「必ず代替日を提案」に対応する
6. 提案された日付は入力欄で書き換えられる。最後に「**延長する**」を人が押して確定させる。
   画面にも「AIによる下書きの提案です」と出るので、**信頼性の担保スライド（10ページ）の内容をそのまま実演できる**。ここまで撮ると、差別化と信頼性を1本のデモで見せられる

### なぜ効くか（撮影時の口頭説明用）
本人は「間に合わない」「一人だと不安」とコメント欄に書いただけで、正式な延長申請はしていない。
それをAIが拾い、責任者には「有給と提出期限を踏まえた代替日」という判断材料つきで上がってくる。
この一連の流れが、課題2の「着手後：声が上がらない」への回答になっている。
